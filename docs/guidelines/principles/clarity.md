# Clarity

Clarity means that every element tells the user what it is, what it does, and what state it is in, without making them work it out. Notable prefers an interface that can be understood at a glance over one that is merely attractive.

## Every cue carries meaning

A surface marks a grouping. A highlight marks where attention or the pointer is. A color marks a status. A shadow marks something that floats above the page. When a visual cue does not communicate one of these things, it is decoration, and decoration is removed unless it serves [Expression](./expression.md).

## States stay distinct

A user should always be able to tell which option is chosen, which one is currently under the pointer or keyboard, which one has focus, and which one is unavailable. These are different facts. A design must not merge them into one visual cue, because the user cannot tell which fact they are looking at.

## Words and visuals agree

A label, an icon, and a state describe the same thing. A control's visible text should be part of its name. An icon should not stand in for a word whose meaning is uncertain.

## Context changes meaning

The same visual treatment can mean different things in different places. A selected item in a list is not the same as an active page in a navigation bar. Components should use the vocabulary of their context, and their visuals should match.

## Principle

A user should understand the state of any element at a glance, and no two different states should look the same.
